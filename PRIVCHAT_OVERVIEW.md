## PrivChat – обзор функционала и развития

### 1. Что это за проект

PrivChat – это **современный мессенджер** с упором на приватность и приятный UI:

- **Backend**: Elixir/Phoenix, Postgres, Phoenix Channels.
- **Frontend**: Next.js 14 (app router), React 18, Zustand‑сторы, адаптивный дизайн.
- **Реалтайм**: полноценные WebSocket‑чаты, presence, индикатор набора текста.

---

### 2. Текущий функционал (что уже работает)

#### 2.1. Аутентификация и аккаунты

- **Регистрация**:
  - поля: телефон, username, пароль, опционально email и display name;
  - нормализация телефона, lower‑case для username/email;
  - валидации формата и длины, уникальность `phone` / `username` / `email`;
  - пароль хешируется через `pbkdf2_elixir`.
- **Логин**:
  - вход по email/телефону/username + пароль;
  - выдаётся JWT, в котором в `sub` зашит `user_id`.
- **Сессия на фронте**:
  - токен и пользователь хранятся в `localStorage`;
  - axios‑интерцептор автоматически подставляет `Authorization: Bearer <token>`.

#### 2.2. Поиск и контакты

- **Поиск пользователей**:
  - эндпоинт `GET /api/users/search?q=...`;
  - поиск по:
    - `username` (без учёта регистра),
    - `display_name` (без учёта регистра),
    - телефону (поддержка разных форматов, нормализация/цифры).
- **Контакты**:
  - `GET /api/contacts` – список контактов текущего пользователя;
  - `POST /api/contacts` – добавление контакта:
    - двусторонняя запись (оба пользователя попадают в контакты друг друга),
    - защита от добавления самого себя;
  - на фронте:
    - `friends-store` (Zustand) с загрузкой, поиском, добавлением;
    - панель “Контакты” / “Поиск по номеру или нику”.

#### 2.3. Чаты

- **Типы чатов**:
  - `direct` – личные диалоги 1‑на‑1;
  - `group` – групповые чаты с несколькими участниками.
- **Прямые диалоги**:
  - уникальный `direct_key` вида `min_id:max_id`, что гарантирует один чат на пару;
  - при открытии список чатов для пользователя строится по таблице участников.
- **Групповые чаты**:
  - создание через UI: модалка “Новая группа”, выбор участников из контактов;
  - владелец + участники сохраняются в `chat_members`;
  - чат сразу появляется в списке у всех участников после обновления списка.
- **Список чатов (frontend)**:
  - хранится в `chat-store` (Zustand);
  - поддержка:
    - закреплённых чатов,
    - счётчиков непрочитанных,
    - черновиков по чатам,
    - фильтров (Все / Непрочитанные / Закреплённые),
    - поиска по названию.
- **Имена чатов**:
  - для `direct` – автоматически подставляется имя/ник собеседника;
  - для `group` – используется заданное пользователем `name`.

#### 2.4. Сообщения

- **История**:
  - `GET /api/chats/:id/messages` – последние N сообщений, с проверкой членства в чате;
  - фронт сохраняет историю по chat_id, сбрасывает непрочитанные.
- **Отправка**:
  - `POST /api/chats/:id/messages` – создаёт запись в БД и:
    - обновляет `updated_at` чата,
    - рассылает событие `message:new` по каналу `chat:<id>`;
  - фронт делает оптимистичную вставку (статус `sending`), потом подменяет реальным ID / статусом `sent`.
- **Состояния сообщений на фронте**:
  - `sending` – только что отправлено, нет ответа сервера;
  - `sent` – сохранено на бэке;
  - `failed` – ошибка при отправке (например, сеть).

#### 2.5. Вложения и голосовые

- **Файлы**:
  - эндпоинт `POST /api/uploads` принимает `multipart/form-data` (`file`);
  - файлы складываются в `priv/static/uploads`, раздаются по `/uploads/<имя>`;
  - ответ содержит `{ name, type, size, url }`.
- **Отправка вложений**:
  - на фронте:
    - скрытый `<input type="file">` + `uploadFile(file)` в `lib/api.ts`;
    - выбранный файл отображается “чипом” над полем ввода;
    - при отправке сообщения вложения уходят в `envelope_metadata.attachments`.
  - на бэке:
    - `Messaging.Message` позволяет сообщения **без body**, если есть вложения;
    - вложения хранятся в JSON‑поле `envelope_metadata`.
- **Голосовые сообщения**:
  - запись через `MediaRecorder` (если пользователь разрешил микрофон);
  - по окончании записи blob → `File` → `uploadFile` → вложение с `kind: "voice"`;
  - в `MessageBubble`:
    - если attachment имеет `kind: "voice"` или `type` начинается с `audio/`,
      рендерится `<audio controls>` вместо ссылки “Скачать”.

#### 2.6. Реалтайм и “печатает…”

- **WebSocket‑подключение**:
  - клиент `phoenix` в `lib/socket.ts`, токен передаётся как `params: { token }`;
  - для каждого чата создаётся канал `chat:<id>`.
- **События**:
  - `message:new` – рассылается при создании сообщения контроллером;
  - `typing` – новый тип события:
    - фронт при вводе текста шлёт `typing: true`;
    - по таймауту/отправке – `typing: false`;
    - канал с `broadcast_from!` не шлёт событие обратно отправителю.
- **UI индикатор**:
  - в заголовке чата, под именем, показывается:
    - либо список участников,
    - либо `печатает…`, если другой участник сейчас набирает текст.

#### 2.7. Уведомления

- **notification-store** на фронте:
  - хранит список уведомлений (сообщения, системные, и т.д.),
  - умеет помечать прочитанными/очищать.
- **NotificationCenter**:
  - мобилка: полноэкранная панель с собственным скроллом, появляется под верхним баром;
  - десктоп: аккуратный дропдаун под иконкой колокольчика, ограниченный по высоте.

#### 2.8. UI/UX и адаптивность

- **AppShell**:
  - десктоп: левый сайдбар (логотип, навигация, профиль, нотификации) + контент;
  - мобилка: верхний бар + нижнее меню, контенту добавлен нижний паддинг, чтобы нижнее меню не перекрывало поле ввода.
- **Чат**:
  - пузырьки сообщений, адаптация под длину текста, отступы, статусы доставки;
  - вложения и голосовые отображаются внутри пузыря;
  - скролл всегда уходит в конец при новых сообщениях.

### 3. Преимущества текущей архитектуры

- **Сильная realtime‑основа**:
  - Phoenix Channels + Presence → легко добавлять новые realtime‑индикаторы (прочтение, онлайн/оффлайн, печатает).
- **Гибкая модель сообщений**:
  - `envelope_metadata` даёт возможность добавлять сложные функции (реакции, реплаи, опросы, системные уведомления) без жёстких миграций.
- **Хорошая разделённость ответственности**:
  - контуры `Accounts` и `Messaging` на бэке;
  - отдельные zustand‑сторы на фронте (`auth`, `theme`, `chat`, `friends`, `notifications`).
- **Подготовка к продакшену**:
  - JWT, CORS, работающие миграции/сидеры;
  - настроенный TypeScript, vitest‑тесты, успешный `next build`.

### 4. Возможности развития и улучшения

#### 4.1. Безопасность и приватность

- End‑to‑end шифрование:
  - шифрование `body` и `attachments` на клиенте,
  - хранение только зашифрованных данных на сервере;
  - механизм резервного копирования и восстановления ключей.
- Двухфакторная аутентификация, ограничение устройств/сессий.

#### 4.2. Богатый контент

- Галерея изображений, предпросмотр документов, inline‑видео.
- Реакции и эмодзи‑реакции к сообщениям.
- Форвард/редактирование сообщений.

#### 4.3. Инфраструктура и перфоманс

- Вертикальное/горизонтальное масштабирование Phoenix (кластер, распределённый PubSub).
- Очереди для тяжёлых задач (обработка файлов, транскрибация голосовых и т.п.).
- Настройка CDN/front‑proxy для статики и вложений.

#### 4.4. PWA и нативные клиенты

- Превратить фронт в PWA с оффлайн‑кэшем и push‑уведомлениями.
- Написать лёгкие нативные клиенты (React Native/Flutter) с тем же API.

---

### 5. Краткое резюме

На текущий момент PrivChat уже предоставляет:

- рабочую регистрацию/логин,
- поиск и контакты,
- прямые и групповые чаты,
- отправку текстовых, файловых и голосовых сообщений,
- realtime‑доставку и индикатор набора,
- удобный адаптивный интерфейс.

При этом архитектура задумана так, чтобы проект можно было развивать до **полноценного защищённого мессенджера уровня production**, не переписывая всё с нуля.
